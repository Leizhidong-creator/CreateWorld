# 工作流验证与结论边界

方法版本1.1.1 · 2026-10-31

验收对象是文件工作流、阅读记录和自然语言粗剧本交接。入口见 [RUN](RUN.md)，方法及职责见 [架构说明](README.md)。本轮未改引擎、模型适配器、数据库和界面，不把方法文件升级称为已接入网页或已验证游戏生成。

## 可重复程序检查

在仓库根目录运行，Python 3.10+、仅标准库：

```powershell
python workflows/story-adaptation/checks/validate_workflow.py
python -m unittest discover -s workflows/story-adaptation/checks -p "test_*.py" -v
python workflows/story-adaptation/checks/validate_reading.py adaptations/<作品标识>
```

工作流检查器核对必需文件、本地链接/锚点、权威规范与上游快照哈希、路径边界和误装的自动发现入口。可加 `--report <工作流目录外的新文件.json>`；报告必须尚不存在，以免覆盖输入或旧证据。退出0代表文件检查通过，不代表文本质量。第三方只读快照中的原链接保留原字节，不当本地运行依赖。

阅读检查器核对来源编号、内容哈希、实际P编号、阅读区间和笔记引用；支持作品根相对路径、阅读账相对笔记及同名笔记锚。拒绝重复JSON键、重复ID、未知引用、非法范围、越界路径及过期摘要。它只能说明声明的覆盖与文件一致，不能证明读取者真读过或理解正确。使用格式见 [阅读账模板](templates/reading-ledger.md)。

两组可携带测试均在checks中：工作流12例、阅读账31例，共43例。前者覆盖有效副本、缺方法/阅读检查器、坏链接/锚、快照篡改、权威哈希不符、意外SKILL、越界快照、首部版本不一致/缺失及历史版本不误判；后者覆盖有效记录、缺段/缺账、编号和路径/哈希/锚点错误、畸形输入及区间合并等。测试不含任何作品剧情或固定篇幅要求。

## 内容审阅须另行执行

原作与视角、改编质量、隔离交接是三个关注点；默认两轮主要修订，不是三个审批阶段。每个问题绑定稿件版本和哈希、位置、依据、影响、处理与复查。纯文件程序不能发现角色未在场、隐秘计划提前泄露或空洞小游戏，不能以检查通过代替这些审阅。

完整流程至少走读一次跳过所有可选内容的主线，区分世界事实、主角认知与玩家披露。新上下文交接只接收粗稿与两规范，不给作者内部解释；只返回问题，主任务统一修改。实际执行记录放各作品work；候选有硬性缺口就保留candidate/blocked，预算到限不是通过。

## 尚未证明

无正式YAML、游戏组装、实际操作、玩家访谈或情绪体验测量。本轮不证明后续作品会自然达到相同质量，不证明全链路无人值守、进程崩溃恢复或网页集成。此后的方法变化应以新的版本与具体复查记录说明，不能沿用旧通过结论。
