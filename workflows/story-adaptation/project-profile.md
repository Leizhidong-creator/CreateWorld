## 上游必须确定

- 类型为 2D 像素剧情；一条主线、唯一结局；主体全程控制同一个角色，持物、衣着、年龄可变化。例外只能来自本作明确授权。
- 有限自由探索，必要事件不可错过。可选内容可有阶段窗口，但完全不参与仍能走完主线，不按收集或评分分流结局。
- 默认预写单线对话，不强制二选一菜单。观察、交谈、调查、操作、等待、受限行动均可参与故事；不强制资源循环。
- 短演出由系统接管角色，演出以必要信息为界。主要参与段落不全退化为走路触发旁白；时间压缩不伪造人物经历。
- 锁定关键因果、关系、人物命运、必要线索顺序、谜题答案、剧情数字及结局。世界真相、玩家知道、角色相信分开，误导需后续澄清。
- 动机通过具体局面和人物回应成立；不以“玩家感动了”代替体验依据。普通失败不改人物命运或创造新结局。
- 普通缺失由 Agent 完整设计，重大冲突询问。来源与用户确认分别保留；Agent 提议被接受仍保留 Agent 归属。

## 下游细化职责

上游确定具体核心参与及其叙事结果，不写操作次数、难度数值、按钮、坐标、状态 ID、条件表达式和存档恢复规格。谜题推理所需事实不能以“下游细节”为由省略。

下游依据基础规范展开对话语义、触发反馈、物件和信息档案、教学、暂停继续、混合恢复、失败、重复、小游戏退出/重开/跳过。独立小游戏成功和跳过接回同一剧情，辅助方式不改结局；上游不得写出与此相冲突的必要条件。普通挑战不自动获得小游戏跳过权。

共通源码的能力承诺沿用基础规范第20节：摇杆、交互、地图、彩蛋、对话、背包、存档/继续、暂停；音效控制不在已供应列表中。这是下游制作约定，不表示本仓库已接入这一套源码。风格算法归外部系统，游戏记录行为并展示结果；上游不编评分阈值。

《高墙之外》YAML 仅用于理解粒度，不是未来任务必需输入。基础规范第24节及其安迪、石锤、收音机、控制瑞德等例子不成为新作品事实或通用例外。新作品不沿用旧作事件数量、篇幅或固定场景。

## 指定角色经历模式

受控角色与叙事视角分别由本作配置确定。“跟随角色经历”意味着不切到角色不在场的独立场面。其他事件需通过角色实际接触渠道或亲历后果进入。默认只看表层意图，是否披露深层计划依本作揭示安排；作者资料的全知不能直接进入玩家提示。

核心机制属于粗稿决定：局部目标、参照、判断/操作、阻力、反馈和接续明确。实现参数仍属下游。本节不改变原有两份规范，也不把任何本作角色变成通用要求。
