# 指定角色经历的完整粗剧本

版本1.1.1 · 入口见 [RUN](../RUN.md)

依据原作笔记、角色经历线与已定转换写 work/draft-vNNN.md。使用 [轻量模板](../templates/game-script.md)，按玩家实际经历连贯写作。整体资料可以揭示故事真相，但必须与游戏实际呈现明确分区。

先写覆盖完整经历的骨架，再全篇展开到同等可交接细度。章数服从经历变化，不照搬小说章数。每个主要片段说明局面和动机、玩家所知、可参与行动、角色/环境回应、下一步；非主角在场的戏不能独立成可观看场面。

视角限定在项目配置指定角色。其他事件只能由原文支持的实际接触渠道进入；若采用不同呈现载体，必须标 Agent 改编并检查是否改变获知时点或知情范围。不能将重要配角的行动转交主角以凑参与。

对话以信息转折、说话者意图及关系变化描述，不逐句复刻小说，不写“双方聊了聊”代替关键语义。感受用处境、行为和回应支撑，不直接宣布玩家感动或理解。

## 核心机制应在粗稿成立

涉及玩法时，明确目标、可用线索/参照、操作或判断、阻力、帮助调整的反馈、局部完成和剧情接续。难度和具体输入可以自由设计，但不能留下从“顺序点击”到“空间拼装”都同样符合的核心空白。安静生活、关系体验可以是低挑战参与，不必人为制造失败。

小游戏独立性、入口和成功回接要明确。细节恢复依基础规范由下游展开；本层标明失败不改人物命运、跳过保留关键行动但不泄露计划，不抄一遍 YAML 规则。单一主线不要求玩家答对整套复杂理论；使用过程反馈帮助理解。

## 隐藏用途和回扣

开发者说明可以写完整真实用途，玩家经历正文只呈现当时允许的信息。分别说明表层任务、可见结果、禁止泄露内容和后续揭晓位置，避免下游把内部解释直接做成任务文案。隐藏深层内心不等于篡改主角实际知情。

揭晓段要连接此前的具体操作与现实结果，不只追加一段理论讲解。没有参与依据时可以保留观察或短演出，不能为加强互动让主角亲历不存在的事。

## 自足交接

正文含作品/版本/范围、主体与视角、整体因果、全部经历章、核心机制、重要取舍与来源、可细化/不可改变范围和真实验证状态。保留剧情数字、答案、角色命运及线索对应，不依赖内部笔记或原书补关键事实。来源定位保留，但下游不必打开原文才知道故事发生什么。

Agent 发明的玩法表示、补充承接、改编载体须定位到章节并说明理由，用户确认不会抹掉归属。不输出游戏代码、状态 ID、条件表达式、逐帧参数和正式 YAML。完成后交 [审阅](script-review.md)，不能自写一行“通过”就发布。

时间跨越采用漫画时，逐幕交代主角经历中的代表事件、前后变化、可知信息和返回操作的承接点；依据见 [时间分镜方法](adaptation-design.md#用漫画分镜压缩时间)。不要把“几年过去”只留成一句待下游重新设计的概括。
