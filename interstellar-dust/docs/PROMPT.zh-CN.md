# 2D 像素剧情游戏生成提示词

> 历史快照：`pixel-story-kit/` 独立目录已于 2026-10-31 从仓库移除。本文保留旧 kit 的提示词与兼容参考；新游戏入口见 [../README.md](../README.md)。

将本文件正文与 `pixel-story-kit.zip` 一起交给 AI。方括号字段可以替换；未填写的内容采用文末默认值。此提示词要求使用随附代码，不应在没有阅读代码的情况下另起一套底座。

---

你是一名同时负责游戏设计、前端开发和交互体验的开发者。请使用我提供的 Pixel Story Kit 通用代码包，制作一款可以从开始玩到结局的 2D 像素剧情探索游戏。

## 一、项目内容

- 游戏名称：[填写名称]
- 故事题材与世界背景：[填写故事或附上叙事材料]
- 玩家扮演的人物及目标：[角色身份、动机、最终想完成的事情]
- 主要人物与关系：[人物列表及彼此关系]
- 情绪和美术气质：[温暖、悬疑、压抑、幽默等；不改变统一像素规范]
- 预计单次游玩时长：[默认 10–15 分钟]
- 已有素材：[填写文件位置；无素材时场景可先用包内基础素材跑通流程；人物必须按第八节调用 character-generation，不得以基础角色替代最终交付]
- 扩展功能：[支线、多结局、失败挑战、小游戏、探索迷雾、线索笔记；未明确要求的默认关闭]
- 发布环境：[默认可静态部署的网页，支持电脑与手机横屏]

保持给定故事的人物动机与因果关系，把关键事件变成玩家能够实际完成的行动。缺少普通细节时做合理补全；只对会改变故事主题或交付范围的矛盾提出集中问题。

## 二、先读取代码包，再开始制作

先阅读 README.md、docs/CONFIG.zh-CN.md、docs/API.zh-CN.md 与 provenance/README.md，运行包内示例，检查 examples/harbor.js 和 examples/station.js 的配置方式。

使用现有 createGame(config)、输入、摇杆、情境按钮、场景、地图、对话、任务、物品、彩蛋、成就、存档和小游戏容器。优先新增内容配置与素材文件，并在 main.js 接入；常规换题材不要修改核心模块。确需扩展时，说明现有接口缺少什么，保持已有配置兼容并补上对应测试。

不要把代码包里的示例剧情直接当作新故事，也不要只交付策划稿、静态画面或无法完成的空流程。代码与素材的使用遵循来源记录，不为上游代码擅自更换许可。

## 三、核心体验与流程

采用“进入故事 → 认识目标 → 探索场景 → 与人物/物件交互 → 获得信息或改变状态 → 推进剧情 → 达成结局”的核心循环。主线必须完整；支线、多结局和失败挑战按配置启用。

普通任务要通过交谈、抵达区域、调查、获得或使用物品等行为推进。必须先后发生的事件设前置条件；可以自由完成的准备事项允许不同顺序。已经提前获得的道具应被后续任务识别，不能形成死锁。

屏幕默认只显示一句当前主线目标。任务更新时简短提醒。复杂操作可以临时显示要求或进度，避免长期堆满任务列表，也不要提前揭露谜题答案。

## 四、基础操作与场景

- 电脑使用 WASD/方向键移动、E/空格交互；M 地图、I 物品、J 成就、Esc/P 暂停。
- 手机使用左侧虚拟摇杆和右侧一个情境交互按钮。按钮随目标显示交谈、调查、开门、拾取等动作；特殊玩法另行说明操作。
- 移动停止后角色立即停下；支持摇杆与按钮同时操作。对话、菜单或地图打开时阻止误操作场景；切后台或失焦清空输入。
- 小场景固定镜头，大场景跟随角色并限制边界；界面不随镜头移动。
- 场景包含背景、前景遮挡、行走区域、碰撞、人物、交互物件、出口和事件区域。画面、碰撞、小地图坐标必须一致。
- 出口条件清楚，落点可通行，避免连续触发来回切换。离开后返回，门、物件和事件状态保持一致。

## 五、地图与引导

使用现有地图模块，呈现玩家位置、场景结构、已知地标及区域级任务引导。跨场景指向可到达的出口；到达目标区域后让玩家自行寻找对象，不持续标出具体人物或物件。支持点击/M 展开与收起，展开时暂停主场景。

未发现的彩蛋与秘密不直接标出。探索迷雾为可选功能；如启用，探索进度纳入存档。出口、地标和区域来自场景配置，不另维护一份不一致的地图坐标。

## 六、对话、任务、道具与线索

普通交谈逐句推进，显示说话人；逐字播放时第一次点击补全当前文字，下一次推进。关键节点可以出现选项，后果由剧情配置；不要求每个选项生成分支。

同一个 NPC 根据进度改变内容。对话可以更新任务、给出物品、记录线索或触发事件，奖励和关键事件只能结算一次。普通对话期间暂停场景风险和倒计时。

道具采用情境自动匹配，背包主要用于查看名称、图标、说明和信件等展开内容。关键消耗或影响分支的交付要让玩家明确选择。缺少条件时给予合理提示。默认不设置负重、容量、装备、合成或随意丢弃。

区分可携带实物与已知信息。证言、密码等记录为线索，不强行做成背包物品；线索笔记面板按需启用。任务、对白、地图和物品读取同一份状态。

## 七、彩蛋、成就与可选玩法

提供与题材相符的少量隐藏内容，可用调查次数、进入位置、停留、物品或剧情条件触发。错过彩蛋不阻挡主线。彩蛋与成就分别配置，并非每个彩蛋都要发成就。

未解锁的隐藏成就显示未知条目，不公开名称和触发条件；解锁后显示名称、图标和说明，并简短提示。不可重复发奖。是否允许重看隐藏内容由配置决定。

需要小游戏时，通过现有容器注册，说明规则并返回成功/失败/取消结果；清理监听与计时器。包内不包含现成玩法，不应声称已有调频、图书整理或迷宫。

失败挑战如启用，要明确原因并允许重试当前挑战。剧情选择造成的另一条故事路径不应自动标为失败。多结局如启用，由前面记录的行动、信息或选择决定；至少一个结局可以完整到达。

## 八、视觉与声音

使用统一视角、像素尺度、角色比例和界面语言。人物、建筑、家具以及图标要协调。角色方向与行走动画相符，移动或转向时外观和大小稳定。像素画面清晰缩放；中文保持足够字号和可读性。

色调、时代、服装、建筑和情绪随故事调整。资源分为场景、角色、物件、界面和演出五类；已启用的功能必须有对应资源。使用背景图片和透明角色精灵支持正式美术，不把基础几何示例当作最终美术要求。

重要操作提供明确视觉反馈，声音作为增强，静音也能理解。提供音乐与音效设置；音频首次交互后启动，切场景和离开页面时正确清理。

### 人物生成：必须使用 character-generation skill

所有需要新生成或重生的玩家角色、主要 NPC，都必须实际调用并遵循 `character-generation` skill。不能只提及技能名称，也不能用手写 SVG、Canvas/Pillow 几何小人、换色示例人物或未经技能流程生成的静态立绘代替该技能的人物产物。

- 每位人物准备一张仅含本人、脸部清晰、接近正面的照片或剧照。优先使用用户提供的参考；影视人物可检索可用的公开剧照并记录来源。缺少合适参考时先补齐或向用户索取，不得静默跳过技能。
- 先读取 skill 及其生成与产物规范，并查看技能提供的风格板、行走布局参考。保留年龄、发型、肤色、眼镜及可见服装；未露出的衣着仅做保守补全并记录。
- 默认使用 balanced 模式，通过内置 image_gen 生成三行四列制作母图：行依次为正面/背面/右侧面，列依次为站立/步态 A/站立/步态 B。正背面的左右脚需交替，侧面需有相反的前后腿步态；左向由右向镜像产生。
- 通过技能脚本完成去背景、二值透明、统一调色板、尺寸/脚点对齐，输出三视图、四方向透明 PNG/WebP 精灵、动画预览、character.json 和 qa-report.json。按技能限制只补生成失败方向，不能关闭或放宽 QA 来宣称通过。
- 对游戏中原本不移动的 NPC，可以接入该技能生成并经独立静态 QA 的 neutral 帧；这只构成静态素材，不等于完整人物动画包通过。若行走 QA 失败，必须保留记录并明确告知用户，不能把静态产物标记为完整动画包。
- 逐项查看三视图、各方向精灵和动画。未通过 QA 的人物不得标记为完成，也不得偷偷换回程序生成小人。最终角色包不得包含源照片或机器绝对路径。
- 将通过 QA 的素材接入游戏。按 character.json 配置方向顺序、每格尺寸、四帧循环、待机帧、帧时长与脚点；保留两个不同步态，不得简单裁成原底座三列而丢掉步态。若底座不支持，做保持旧配置兼容的最小渲染扩展并添加行为测试。
- 实际验证主角四方向行走和停止、NPC 显示、透明边缘、脚点与碰撞位置，以及小场景/大场景下的比例。交付注明每个人物的生成模式、调用次数、参考来源、保守补全和剩余 QA 警告。

## 九、存档与完整性

使用新的游戏 ID 隔离存档。保存任务阶段、物品、线索、选择、场景变化、探索与一次性事件。本局进度与长期成就、结局和设置分开。重新开始只重置本局；清除全部记录提供明确确认。

确保资源全部可加载，无远程 CDN 依赖；无法加载或存储不可用时给出清楚提示。不得静默丢失进度。界面开关、转场、读档和重开后都不能出现重复奖励、遗留方向、卡住的按钮或不一致状态。

## 十、完成与交付

交付完整可运行项目、修改过的内容配置与素材、中文运行说明，以及验证结果。先完成主线闭环，再完善扩展与演出。

运行 npm run check 与 npm test；新增核心能力时添加行为测试。实际用键盘和触屏走通，从标题进入、完成主要任务、到达结局，并验证刷新恢复、重新开始、地图、物品、成就、音量和场景碰撞。最后从独立打包目录启动一次，确认不依赖开发机上的其他文件。

未填写时默认：三至五个场景、三至五位主要 NPC、一个完整主线、一个结局、三个彩蛋或探索成就；不增加战斗、联网服务、复杂数值系统或现成小游戏。保留情境交互、区域级地图引导、简洁目标、关键对话选择及自动存档。完成后说明哪些功能已验证、哪些素材仍是示例替代品。
