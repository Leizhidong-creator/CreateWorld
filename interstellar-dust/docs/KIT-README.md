# Pixel Story Kit · 2D 像素剧情游戏底座

> 历史快照：`pixel-story-kit/` 独立目录已于 2026-10-31 从仓库移除。本文仅保留旧 kit 的使用与兼容参考，实际运行入口见 [../README.md](../README.md)。

可运行的网页游戏底座、可独立导入的模块、两套内容配置，以及指导 AI 使用它们的中文提示词。基于《Beyond The Walls》相关代码抽取与重构；来源和使用限制见 [provenance/README.md](../provenance/README.md)。本包不改变上游代码的授权范围。

## 30 秒启动

需要 Node.js 20 或更新版本，无需 `npm install`，无需构建：

```sh
cd pixel-story-kit
npm start
```

打开终端显示的 `http://127.0.0.1:4173`。端口占用时运行 `npm start -- --port 4180`。也可在此目录运行 `python3 -m http.server 4173 --bind 127.0.0.1`。ES Modules 与资源加载需要 HTTP，请不要双击 HTML 使用 `file://`。

- 默认示例：雾港来信，三场景、四阶段主线、四个成就、两种收尾。
- 第二配置：标题页点击“轨道余声”，或打开 `/?theme=station`。它复用布局与基础素材，换主题文字、色调、物品叙述和线索面板，不修改核心模块。
- 桌面：WASD / 方向键移动，E / 空格交互，M 地图，I 物品，J 成就，Esc / P 暂停。
- 手机：横屏，左侧摇杆＋右侧情境按钮。触屏两指可分别移动和交互。键盘和触屏始终可用。

示例通关路线：离开小屋 → 庭院右侧与守灯人交谈取得钥匙 → 西北档案室调查中央桌子 → 东北信号灯 → 回守灯人处选择回应。地图指向相关区域或出口，进入目标区域后不继续定位具体物件。提示框、地图、物品与暂停菜单会暂停主场景。

## 从这里开始改编

1. 阅读 [最终提示词](docs/PROMPT.zh-CN.md)，与 ZIP 一起交给 AI。
2. 复制 `examples/harbor.js`，修改游戏 ID、故事配置和素材清单。
3. 按 [配置说明](docs/CONFIG.zh-CN.md) 设置场景、互动、条件与动作。
4. 在 `main.js` 选择新配置；优先保持 `src/` 不变。
5. 执行 `npm run check`、`npm test`，再从开始到结局完整试玩。

代码逻辑可以复用；示例 SVG 与程序化音效用于验证功能，正式游戏应提供与题材相符的场景图、角色精灵和音乐。支持整张背景图及对象贴图，不强制使用示例的几何绘制外观。

## 包内组成

- `src/`：运行、状态、输入、摇杆、场景几何、渲染、地图、UI、资源、存档、验证与小游戏容器。
- `examples/`：两个配置示例；不包含原游戏的剧情、场景美术或三个具体小游戏。
- `assets/`：原生 SVG 像素角色、摇杆图形、图标和合成 WAV。无需网络 CDN。
- `docs/`：配置、接口、扩展、最终提示词和验证记录。
- `tests/`：Node 内置测试；`plugin-fixture.html` 用于在浏览器测试小游戏容器，不属于游戏内容。
- `provenance/`：固定版本上游源码片段、完整原控件源码、来源映射和使用限制。
- `scripts/`：本地服务器、检查、素材生成、打包工具。

## 检查与打包

```sh
npm run check
npm test
npm run package
```

打包命令需要 Python 3，只使用标准库。默认 ZIP 写到代码目录旁边；也可 `python3 scripts/package.py --output /your/path/pixel-story-kit.zip`。包内的 `MANIFEST.sha256` 记录每个交付文件的校验值。

## 已实现的通用行为

- 小场景固定镜头，大场景跟随并限制边界；脚部碰撞、分步移动防止高速穿墙；对象与人物按脚点遮挡排序。
- 场景、任务、对白、物品、地图和成就共用一份可序列化状态。
- 普通线性对话＋关键选项；逐字显示，第一次交互补全，后一次推进。
- 道具自动匹配交互目标；重要交付通过明确选择进行；信息线索与实物分开。
- 场景触发器可按位置、条件、停留时间触发；交互次数可用于彩蛋；已发现成就只解锁一次。
- 隐藏成就未解锁时展示“未发现”；图标和名称在发现后公开。
- 自动保存任务/交互/转场节点及每五秒的探索进度；暂停、切后台和返回标题时保存。
- 重新开始清除本局数据、保留成就、结局记录和设置；设置页可单独清除本游戏所有记录。
- 小游戏容器支持注册、加载、输入接管、成功/失败/取消、销毁；具体玩法由内容项目实现。

## 明确边界

没有联网账户、云存档、联机、战斗、复杂背包、自动寻路、地图编辑器、人物日程和行为评分。支线可通过 `optional` 任务表达，多结局可通过条件与动作配置；不会自动生成故事内容。第一版使用矩形碰撞，不提供多边形编辑器。中文使用系统字体，优先保证清晰。
