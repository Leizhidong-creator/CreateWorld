# 创意补全与文本流程组合

日期：2026-10-31。固定依赖：`@create-world/creative-completion@1.0.0`。

## 组合方式

使用独立包的模块接口接入，不启动第二个 HTTP 服务，也不要求前端分别调用两个后台。新项目仍使用 `/api/text/projects`，启动 `kind=script` 后，第一块执行：

**创意判断／必要补全 → 原文与创作稿阅读 → 改编设计 → 完整粗剧本 → 审阅。**

粗剧本完成后停留，支持查看、编辑和 AI 候选采纳。用户另行启动 `kind=yaml` 后才进入 YAML 制作与自审。AI 改稿和 YAML 任务不重新跑创意补全。

旧任务没有新版 `stages` 字段时保持原有阶段顺序；不会因为升级而在恢复途中插入创意重写。独立包源码、原压缩包和原独立接口未修改。

## 来源与边界适配

- 已有完整文本由独立包按内容判断 direct，交接正文逐字符保持不变。
- 稀疏原创由独立包判断 targeted/expand，并经过其独立审查后才交接。包输出 ready 只表示设计稿可以进入改编，不表示游戏完成。
- 仅作品名称绕过创意模块，先走原文获取与核对，不能创作一本小说来代替缺少的原文。
- 独立包最多接收 50000 字符正文和 2000 字符方向要求。超过时不裁剪、不分块后冒充全文判断，而是完整交给原有阅读与改编流程；交接记录明确标记 bypassed 及原因。这不是按字数判断作品是否完整。
- 创意补全阶段显式使用 inspect/dialogue/activate/inventory 四类能力，加入单主线、唯一结局、固定角色及保留已指定事实等约束，避免包默认的多结局能力改变已确认边界。独立包的最多 6 场景、8 角色、8 段只限制这次种子补全；不成为下游完整游戏内容的数量上限。
- 不可读材料先请求用户提供可替代的完整正文；原文件仍留存，替代关系写入 sourceExclusions，不把损坏文件计为已经完整读取。

后续阅读使用完整 `adaptationInput`，同时读取约束、方向、澄清、创意稿玩法建议与来源标记。`ai-expanded` 始终是 Agent 设计，原始用户输入仍独立保存。粗剧本需把下游必需的设计与来源说明写入正文，YAML 不能依赖这个内部交接文件补剧情。

## 接口兼容

原接口、启动请求及回答请求不变。新增：

| 字段／事件 | 含义 |
|---|---|
| `run.stage=creative` | 第一块的创意入口处理阶段 |
| `run.stages` | 该次任务固定的阶段顺序，用于兼容旧任务恢复 |
| 项目详情 `creativeLinks` | 文本任务与当前独立包任务的关联 |
| 项目详情 `creativeJobs` | 已返回的创意任务记录、判断、结果及实际模型调用计数 |
| `model.creative.job` | 当前创意子任务的关联事件 |

小人职责继续使用 `adapter`，不新增并行 Agent。独立包的 `needs_input` 被转换成现有 question.created 气泡，包含稳定问题编号、批次、完整原问题与判断依据。超过气泡长度的原问题放入 details。回答仍走现有 answer 接口，创意问题自由文字最多 4000 字符，更多材料可上传引用。

所有必要问题回答后，保留原始输入，携带 clarifications 创建新的创意子任务；旧任务保留用于追溯。澄清超出独立包的 10 组限制时明确失败，不丢弃早期答案。普通缺失自动补全，不额外增加逐阶段确认。

创意补全失败或未审查通过时，不进入粗剧本生成。停止父任务会取消子任务，迟到响应不发布。用户继续时复用相同输入对应的子任务及有效检查点；独立包的累计次数、时长和尝试预算仍有效，不能用父任务恢复绕过它。

## 最终 YAML 到游戏的交接

本包仍只参与第一块的创意处理。YAML 自审完成后等待用户明确确认，之后由宿主自动交接到现有整部游戏制作入口；不会让创意包再改写最终 YAML。接口和后续游戏修改边界见 [TEXT-GAME-HANDOFF.md](TEXT-GAME-HANDOFF.md)。
