## 研究与使用说明

本目录用于为 Create World 的 AI 制作流程提供候选机制，不把任何商业作品的角色、关卡、名称或美术搬入项目。条目是对常见益智、探索、观察、资源管理和轻量动作结构的抽象，使用时必须根据当前故事的目标、阻碍、因果和玩家身份重新设计。

整理时参考了公开的谜题游戏分类、PuzzleScript 的公开编辑器与示例说明，以及本项目已有的 `MiniGameHost`、`registerMiniGame`、真实输入旅程和插件合同：

- Wikipedia，List of puzzle video games：https://en.wikipedia.org/wiki/List_of_puzzle_video_games
- PuzzleScript，公开规则编辑器与示例入口：https://www.puzzlescript.net/
- Create World runtime API：`interstellar-dust/docs/API.zh-CN.md`
- Create World 扩展合同：`create-world-workbench/packages/compiler/CONFIG.md`

网络资料只用于发现和归纳机制类别；每个具体游戏接入前仍须由 AI 写出本作的规则、反馈、成功、失败、取消、状态效果和真实输入测试。

## AI 选用协议

1. 先读取本文件，再读取 `gameplay-design`、`interaction-generation` 和 `packages/compiler/CONFIG.md`。
2. 从 100 项中选 1 到 3 项作为候选，不按编号机械套用。选择理由必须对应故事中的目标、阻碍、已知信息和可操作对象。
3. 合并相似玩法时只保留一个清晰规则；不要为了满足“小游戏”硬塞弹窗。
4. 将选中的结构改写为 `design.json` 的 mechanism：`storyBasis`、`goal`、`information`、`inputs`、`rules`、`feedback`、`success`、`failure`、`cancel`、`implementation`、`tests`。
5. 在 `extensions/*.js` 中通过 `game.registerMiniGame` 或 `game.registerAction` 实现。`game.json` 声明 `minigames`，`journeys.json` 必须覆盖错误操作、重试、取消和成功。
6. 优先使用可读、可撤销、可重试的小规模规则；禁止用随机猜谜、强制等待、重复点击或“点击完成”代替机制。
7. 机制必须改变剧情状态或可达路径，并通过真实键盘或触屏输入验证；纸面描述、代码文件存在和模型自述都不能代替浏览器证据。


# 100 种小游戏与小解谜机制库

### M001　灯号记忆

玩家面对一个与当前剧情相关的具体目标：观察一组依次亮起的灯号并按同样顺序重现。这个目标应放在可理解的场景对象上，例如设备、文件、道路、角色或环境，而不是凭空出现的菜单。AI 需要先说明玩家为什么要做这件事，以及完成后谁会受益、哪个障碍会改变。

核心规则是：每轮增加一个符号，输入错误立即显示错位位置，可选择重试或退出。制作时应把规则拆成少量可观察状态，让每一次点击、按键、拖动或移动都产生反馈。正确操作要逐步接近目标，错误操作要显示原因并允许修正；取消应回到交互点，失败应有重试或替代路径。小游戏的输入必须使用运行时已有的 click、key、drag、cancel 等真实输入形式，并由插件返回 success、failure 或 cancel。

剧情适配方向：适合把记忆设计成无线电报码、窗灯、星图或角色暗号；成功可开启设备，失败可触发误报。。实现时可以改变符号、节奏、难度和视觉语言，但不能把本条原样套进所有故事。选中后要把它写入 `design.json` 的机制规格，明确状态效果、成功和失败后的动作，并在 `extensions/*.js` 中实现可销毁的 `mount(container, ctx)` 组件。

验收时至少安排一次错误输入、一次重试、一次取消和一次满足真实规则的成功输入；成功必须改变旗标、物品、任务、场景或结局条件。若该机制不服务故事推进，应放弃它或改成普通场景交互。
