# 故事游戏对白

读取当前场景、人物、原作依据与统一状态，区分玩家本人和被操控角色的知识。保留版本、动机和语言环境；创作新表达，不复制原作大段对白。
先明确这次交流的叙事或操作作用，再写内容。普通对白直接交付一个可用版本；关键交流需要时才比较不同写法，不强制每段多稿评分。
对白要回应对方，避免任务日志式轮流说明。同一信息不要在旁白、任务和NPC之间重复解释；重复调查返回简短反馈。没有奖励的必要人物交流可以保留，不机械删除。
使用框架原生格式，明确触发、知情、选择与完成结果。保持简洁可读，但不设强制字数配额。取消或中断不能提前领取完成奖励。

在本次已有写作与文本检查中执行[素材与内容边界](../visual-asset-production/references/content-boundaries.md)。结合上下文判断实际表达，正常武打叙述、死亡事实、恋爱与严肃简述伤害经历不因关键词拦截；避免色情细节和以折磨为重点的残酷描写。问题沿用已有记录，只修相关片段，不增加独立审核或逐句审批。
需要细致声音设计时再读 references/conversation-craft.md；影视连续性问题再读 references/film-adaptation-workflow.md。旧canvas-room格式与其专用校验器不是当前工作台合同。

在 Create World 工作台内使用时，先按需读取 [项目接入约定](references/workbench-v2.md)。技能可在完整任务中重复调用，不规定固定流水线。旧格式参考仅用于对应旧项目，不能覆盖当前合同。
