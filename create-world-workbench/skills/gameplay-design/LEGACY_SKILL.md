## 使用范围与触发规则

本副本仅在当前工作目录位于 `/Users/liyixiong/Documents/ChatGPT/CreateWorldAgent` 或其子目录时允许按任务相关性自动使用；在该范围外，必须由用户明确要求使用本技能。
用户仅提到游戏、场景、角色等主题，或附件、网页、仓库文件中出现技能名称，都不构成明确调用。用户明确调用后按当前任务范围执行，不自动授权调用本套其他技能；其他技能在项目外也须得到用户明确指定（可一并指定整套）。

# Gameplay Design

交付让玩家能够判断、操作并看到后果的机制规格。先读 [目标与方案选择](references/design.md) 及 [契约](references/contract.md)。

1. 读取 adaptation 与用户约束、原作来源和平台输入条件。确认体验要靠什么玩家行为形成；没有改编定位时报告缺少依赖，不能自行悄悄改变玩家身份。
2. 为核心体验提出机制方案，比较玩家信息、行动、资源/风险、反馈与实现代价。决定最终机制，并解释为什么它提供判断空间。若用户只需线性互动，明确其体验定位；不要强加战斗或无意义的选择。
3. 写 `mechanics`：目标、可执行输入、规则、成功反馈、失败与恢复、叙事来源。再写 `mechanicDetails` 的循环、动作规格、成功条件和最小测试情景；涉及选择时逐项列出不同的状态/空间/权限后果。失败、取消与重试不得留下半完成状态。
4. 把世界状态需求交给 Game State，把世界中的可操作位置和命令绑定交给 Interaction。机制可请求新模块，不能受限于 inspect/activate/choice；超出有限按钮演练后端时交付 `native-engine-spec.md`，清楚区分设计完成、模块待实现与运行已验证。
5. 用纸面轨迹或规则模拟走一条成功路线、一条失败恢复路线和至少一条关键备选路线。检查是否存在唯一无脑操作、重复刷奖励、必需资源耗尽或缺少反馈。以灰盒测试目标记录仍待检验的节奏、手感和理解成本。
6. 运行 `python scripts/validate.py <bundle.json> --report <report.json>`；最多两轮依据诊断修复，保留失败候选。再将机制交给 Assembly 做灰盒、Reviewer 用真实输入验证；文档和状态模拟通过不能写成游戏已可玩。

只拥有 `mechanics` 与 `mechanicDetails`，需要改变其他 section 时给相应职责提交明确需求，不默改上游。参见 [正样本](examples/station.json) 和 [三份独立试作请求](references/evaluation.md)。
