# Gameplay Design：实现前目标与决策

目标：让改编定位变为可操作、可反馈、可重复的玩法循环。解释玩家掌握什么信息、选择什么动作、承担什么代价，以及成功、失败、取消和恢复如何发生。

预期效果：至少一个核心机制提供真实判断空间，玩家决定会改变资源、位置、权限、风险或后续行动；不能用一串“点击继续”冒充机制。输入方式必须对应目标平台，每个机制有可实现的模块边界和验证情景。

方案比较：只有动词清单不能约束状态后果；为所有机制预设 inspect/activate/choice 会重复旧模板限制；完全自由代码又使设计与实现难以归因。采用开放机制类型、结构化动作与规则、可执行小型规则样例，并由后续 Interaction/State 绑定实际命令。设计阶段允许创新机制，未知引擎或模块能力显式进入实施计划。

范围：这是玩法设计与规则可验证性入口，不负责美术生产，不宣称文档就已实现游戏。平衡、手感、动态 AI、随机分布与连续物理需要灰盒及实测。可确定检查的范围集中在动作引用、循环闭合、输入可用、决策差异、失败恢复和成功条件。

核验计划：正样本覆盖推理与资源取舍；反样本覆盖单向死循环、同效选项、无恢复失败、重复动作、未支持输入、循环悬空、体验无机制承担。三份独立前向请求跨调查解谜、资源分配和潜行。通过契约后必须组装灰盒并用玩家输入验证，不把规则模拟称为真实玩家测试。

方法依据：项目制作架构报告及其引用的 MDA 思路；把机制产生的动态行为与预期体验分开陈述并分别验证。
