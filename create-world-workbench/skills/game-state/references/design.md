# Game State 实现前决策

目标：让跨场景、对白、小游戏和存档共享一个可审计的权威状态，避免不同界面私自设置完成标记。效果应是同一初态和动作序列得到相同结果；非法输入、越界效果和异版存档拒绝且不改变原状态。

候选方案：任意 JavaScript reducer 表达力高但需要隔离执行；纯文本状态表不可运行；有限类型声明加 guard/effect 解释器可直接验证并穷举。此版本选择第三种，支持布尔、有界整数、有限枚举，拒绝未声明状态与动态代码。它是可执行灰盒参考协议，不替代未来经隔离审查的自定义玩法模块。

状态契约先由玩法和主流程提出需求，Game State 负责字段所有权、初始值、范围、迁移、复位及存档版本。Interaction 只能引用声明的字段。迁移是原子事务，逐项效果按声明顺序运行；任何失败回滚全部效果。完成 token 支持一次性动作；终局停止普通动作。检查点绑定完整输入哈希，不能把制作检查点当玩家存档。

验证计划：真实 CLI 重放、多次重放确定性、未知动作、知识 guard、整数越界、一次性奖励、非法枚举、错误/篡改/异版检查点；有限状态可达性、死锁与结束可达性。搜索触及预算后结果必须是 unknown，不得把已探索部分当完整证明。模型和浏览器分别验收，状态穷举不能证明 UI 绑定。

稳定性声明仅覆盖本协议内的有限确定性状态，不包含连续物理、网络并发、未定义自定义代码，也不把测试次数当模型生成成功率。
