## 使用范围与触发规则

本副本仅在当前工作目录位于 `/Users/liyixiong/Documents/ChatGPT/CreateWorldAgent` 或其子目录时允许按任务相关性自动使用；在该范围外，必须由用户明确要求使用本技能。
用户仅提到游戏、场景、角色等主题，或附件、网页、仓库文件中出现技能名称，都不构成明确调用。用户明确调用后按当前任务范围执行，不自动授权调用本套其他技能；其他技能在项目外也须得到用户明确指定（可一并指定整套）。

# Game State

先读 [目标与方案](references/design.md) 和 [契约](references/contract.md)。世界状态、制作任务检查点、Agent 线程是三种不同对象，不得混用。

1. 读取已确认的改编、玩法、主流程、分支及宿主状态实现。列出每个事实的初值、唯一写入动作、读取者、生命周期与存档需求。沿用原有 ID，禁止每个界面私藏一份剧情变量。
2. 区分永久事实、可消耗资源、派生显示值、局部临时状态。派生值能计算时不重复存储。对数字资源给边界，对互斥状态用枚举，对奖励定义幂等语义；为原作不变量写明确条件。
3. 先确定 guard，再以事务计算 effects；任一类型、范围或不变量失败则全部回滚，界面不跳转。成功之后才派发显示与动画事件。取消、拒绝与重试不能领取奖励。
4. 在 bundle 中生成或修订 `state`；需要改变已有交互时列明依赖修订，不暗改对白、关卡或已发布产物。另交 `state-design.md` 记录读写表、存档版本、迁移策略及尚未实现的原生引擎需求。
5. 执行 `python scripts/validate.py bundle.json --report state-report.json`。它枚举当前有限模型，输出结局见证和软锁反例。超过上限是验证未完成，不能当通过。
6. 用 `python scripts/simulate.py bundle.json --actions start,... --save checkpoint.json` 回放实际声明动作，再用 `--restore checkpoint.json` 恢复。保存包含输入指纹和动作轨迹；不兼容版本或伪造状态应拒绝，不静默清空旧存档。
7. 在宿主运行时验证同一条动作序列、暂停、重开和存档。静态模型通过不代替真实操作；记录模型和浏览器证据分别是否通过。

连续物理、随机 AI、多人状态不能假装被有限枚举证明；保留本技能的单一写入与事务原则，为原生引擎定义种子、时间步、事件日志和相应测试。最多两轮有依据的自动修复；仍失败保留候选和诊断，不能删不变量换取通过。

独立运行示例和反例在 `examples/station.json` 与 `tests/test_state.py`。运行 `python -B -m unittest discover -s tests -v`。前向任务见 [评估](references/evaluation.md)。
