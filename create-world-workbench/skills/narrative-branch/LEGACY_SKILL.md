# Narrative Branch

交付可组装、可回放的分支，而不是选择树梗概。先阅读 [目标与方案](references/design.md)，再按 [产物契约](references/contract.md) 工作。

## 制作

1. 读取原作来源、不可改事实、改编取舍、主流程、世界变量及已存在的交互。保留它们的 ID 与修订；依赖缺失时列出缺口，不以自造事实补足。
2. 对每个候选选择写清楚玩家在决策时知道什么、可预见什么、承担什么代价。用两个合理动机形成取舍，不用显然正确和显然错误的同义按钮凑数。忠实固定结局可保持空分支。
3. 先设计后果，再写按钮文案：至少影响行动权限、资源、人物关系、空间路径或玩家可得信息。为延迟后果登记状态变量的提出方、写入动作、读取位置与保留期限。需要新变量时提出 State 修订，不能暗中扩充世界。
4. 将选择挂到明确的决策界面，绑定已有或提出的新动作。写 guard、effects、汇合点和结局条件。多个分支共享变量时逐项检查顺序影响；汇合保留仍有叙事意义的事实，不能因为回到同一场景就清空选择。
5. 先完成一条主线，再加一次侧路、一次回访和一个延迟回报。对于互斥任务给出关闭/失败反馈；对可错过内容标明时间窗及替代信息，不能让关键知识只存在于可永久错过支线。
6. 更新 bundle 的 `branches`，将新增动作和变量作为明确的依赖变更提交，并交付 `branch-design.md`：来源/新增差异、选择理由、状态读写、汇合策略、未解决问题。参考 [制作示例](examples/authoring.md)。

## 核验和修复

```text
python scripts/validate.py bundle.json --report branch-report.json
python -B -m unittest discover -s tests -v
```

脚本从真实初始状态枚举合法动作，检查选项可达、执行后果不同、每个选项能达到声明结局，并返回最短证据路径。用这些路径在组装后的游戏里实际点击/按键复现；状态观察只能读取。

逐条人工核对：文案是否诚实提示取舍、因果是否忠实、延迟后果有没有被后续动作抹掉。脚本不能凭字符串理解这些问题。保留失败 JSON、报告和修订原因；修复负责该问题的分支或上游状态，不能删除失败选项或降低故事约束换取通过。

有限模型超限返回验证未完成。物理潜行、并行时间线或自由行动分支可交付原生模块规格与引擎测试计划；不能把原需求压成有限按钮后声称已实现。仅模型检查通过时标记 `model_checked`，实际 UI 未测写 `runtime_unverified`；不要写“稳定可用”。

独立前向评测使用 [评测任务](examples/eval-prompts.md)，先执行陌生任务再检查实际产物，不把预期答案塞进生成提示。
