# Game Adaptation：实现前目标与决策

目标：把完整叙事材料与用户的制作约束转为可执行的游戏定位。回答类型、玩家身份、核心体验、玩家实际行为、保留与改写的因果、制作范围。产物不代替原作结构，也不提前写完关卡。

预期效果：下游能据此设计不同的玩法，而不是把所有故事套成收集钥匙。原作中的每个事件都要有保留、转化或省略的说明，新增情节显式标为原创；关键因果被改写时保留理由与体验后果。每项体验必须落到玩家可控制的行为。

方案比较：纯长文 brief 易读但引用、覆盖和约束不可自动核验；一次生成整个游戏会混合改编与实现失误；采用带稳定 ID 的 brief 加事件映射账本，可以分别审查语义和结构，并供玩法及流程引用。因此采用第三种，保留简洁人类说明与机器契约。

范围：支持线性故事或已有结构化 narrative 的单人 2D 改编；不强制某种引擎、谜题或结局数量。没有完整原作时列明缺口，不将补写算作原作事实。不自动把预算不支持的动作、美术或联网需求标成可用。

核验计划：确定性检查事件覆盖、悬空引用、重复 ID、体验到行动映射、用户指定身份/类型/平台/时长和能力预算；使用正样本及删掉事件、违背硬约束、空行动、误标原创等反样本。独立模型前向试作验证是否能产出合理改编，而不是只填字段。程序通过仅代表契约一致，主题忠实与吸引力仍需内容审阅或玩家证据。

方法依据：项目 docs/research/06-skills-production-architecture.md 中制作职责与依赖图；关注“体验 → 玩家决策 → 规则”的对应关系。没有把本地契约称为上游流水线完整执行。
