## 使用范围与触发规则

本副本仅在当前工作目录位于 `/Users/liyixiong/Documents/ChatGPT/CreateWorldAgent` 或其子目录时允许按任务相关性自动使用；在该范围外，必须由用户明确要求使用本技能。
用户仅提到游戏、场景、角色等主题，或附件、网页、仓库文件中出现技能名称，都不构成明确调用。用户明确调用后按当前任务范围执行，不自动授权调用本套其他技能；其他技能在项目外也须得到用户明确指定（可一并指定整套）。

# Game Adaptation

交付可审阅、可供 Gameplay/Main Flow 使用的改编方案，保留用户指定的角色、类型和结局约束。先读 [设计目标](references/design.md) 与 [输入输出契约](references/contract.md)。

1. 读取完整原作结构及来源定位、用户限制、目标平台和当前制作能力。保留已有 Content Understanding 原文件，通过附加映射接入；缺少材料或原作不完整时写出缺口，不凭摘要补齐事实。
2. 先说明本次改编要让玩家承担什么角色、获得什么体验、亲自作什么判断。比较真正不同的可实现方案，例如推理重建和资源分配，而非相同玩法的不同美术外皮。明确选择理由；用户已决定的部分无需再次比较。
3. 把每个核心体验落实到可操作的动作与后果；写出核心循环假设、信息来源、风险、失败恢复和范围。玩法细化交给 Gameplay；没有真实模块能力的部分标为待实现，不能冒充现成能力。
4. 给每个原作节点记录保留、改写或省略，改写与省略必须解释理由；新增内容标为原创。检查因果、角色知情范围和固定结局，避免改编者解释泄漏为玩家起始知识。
5. 在候选 bundle 中只更新 `adaptation`，保留原始输入与版本。输出简短 `adaptation-rationale.md` 说明最终定位、取舍、硬约束和需要灰盒验证的假设。若要求真实物理、实时战斗等，另交 native-engine spec，不把请求缩成按钮清单。
6. 执行 `python scripts/validate.py <bundle.json> --report <report.json>`。修复实际错误后重新检查；最多两轮自动修复，仍失败保留候选与具体阻碍。最后人工/模型语义审阅原文因果和体验映射。验证器不证明故事忠实或好玩。

详细正样本见 [examples/station.json](examples/station.json)，独立评估请求见 [references/evaluation.md](references/evaluation.md)。在工作台中，候选写入 agent 可写运行目录，宿主负责提交验证产物；不要修改已验收发布或现有五项 skill。
