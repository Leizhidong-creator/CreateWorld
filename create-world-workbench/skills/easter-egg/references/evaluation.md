# 独立前向评测

这些是待执行任务，不能把任务存在写成评测通过。每次在全新目录给技能真实材料与以下需求，不提供 examples/station.json 的答案；完成后再由另一个审阅步骤比较要求与实际产物。使用用户指定模型，保留模型名、输入、输出、耗时、失败与修复次数。

1. 为旧车站设计隐藏纪念物，不收集也能达到所有成功主结局；提供跳过轨迹。
2. 隐藏信件提到后期反转，设计知识门槛并检查任意发现时机都不提前泄漏。
3. 彩蛋可重复领取资源但主线有限，检查重复奖励、主线依赖与不适合加入时的空包取舍。

每项先不干预执行一次：检查加载正确技能、目标分析、候选方案选择、完整产物与来源，实际运行脚本并记录退出码。允许最多两次按缺陷修复，首轮与修复后结果分别统计。严禁改变用户硬约束、伪造证据或把未实现的模块标为已运行。

评分维度：需求满足、行为因果、依赖契约、可执行核验、失败诚实性，各 0–2 分；记录具体产物证据，不能只写总分。出现错误来源、伪造测试、未声明能力替代即不能通过。结构测试与用户试玩分开；未经实际模型执行，成功率写未测，不填 100%。

运行包内正反例：python -B -m unittest discover -s tests -v。它只测试校验器与执行规则，不是上述创作评测。当前长期稳定性需要更多陌生题材重复样本，不能用同一夹具重复运行次数代替独立样本。
