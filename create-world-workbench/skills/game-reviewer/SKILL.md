# 游戏实现与实际验收

在当前这一次审阅中读取并执行[素材与内容边界](../visual-asset-production/references/content-boundaries.md)，复用已提供的图片、动作证据、对白、实现和操作结果。允许正常武打、少量血迹与正常恋爱，禁止色情及过度血腥、残酷；不能按关键词、武器、露肤或无依据联想拦截。结合连续动作及互动判断，不把截图当作未查看动画/分支的证据。普通通过项简记实际查看范围；问题写入现有 issues，具体未验证项写入 unverified，内容结论与检查状态分开。明确越界令总 passed=false；内容问题不伪报为美术 visualPassed 或六项失败。只补看必要的相关证据，不另起审核调用、固定轮次、逐项审批或新验收机制。

正式交付必须按 [统一美术规格与合成验收](../art-direction/references/visual-standard.md) 检查实际运行截图，在 `review.json.visualConsistency` 逐场景记录六项观察。明显的角色/背景/家具风格冲突是交付缺陷，应令 `visualPassed=false`；不得因玩法测试通过而降为普通建议。只有规格或单独素材截图不能证明合成一致。

对照用户要求、原作约束和mechanics核对实际实现，尤其检查操作是否真的改变局面、关键机制是否被删除或替换成成功文字。
程序检查引用、状态与资源；宿主浏览器以真实输入检查流程和机制；模型实际看图与阅读内容，检查视觉、因果、知情、重复与无作用节点。三类结论分开，不能互相冒充。
覆盖完整主线、跨场景条件、回访、提前拿物品、简单小游戏成功/失败/取消、存档恢复、重开。机制测试要对应规格，并保留操作和结果，不能只确认文件存在。
区分阻断缺陷和不影响操作、识别的细小视觉瑕疵；后者记录为建议，不要求为零。可走多边形外框不等于墙，不能把内部交互式出口误判为封闭。缺陷给可复现动作、预期/实际与负责位置。允许自主返回设计或实现修复，不允许删约束、删路径来过验收。只重跑受影响检查与必要回归。
约10分钟是内容估计；自动速通时间不是玩家时长。未做真人体验明确未验证，不判断玩家偏好。单作品成功不等于任意故事稳定生成。

在 Create World 工作台内使用时，先按需读取 [项目接入约定](references/workbench-v2.md)。技能可在完整任务中重复调用，不规定固定流水线。旧格式参考仅用于对应旧项目，不能覆盖当前合同。
