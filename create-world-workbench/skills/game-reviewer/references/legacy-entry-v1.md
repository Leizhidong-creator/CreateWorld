## 使用范围与触发规则

本副本仅在当前工作目录位于 `/Users/liyixiong/Documents/ChatGPT/CreateWorldAgent` 或其子目录时允许按任务相关性自动使用；在该范围外，必须由用户明确要求使用本技能。
用户仅提到游戏、场景、角色等主题，或附件、网页、仓库文件中出现技能名称，都不构成明确调用。用户明确调用后按当前任务范围执行，不自动授权调用本套其他技能；其他技能在项目外也须得到用户明确指定（可一并指定整套）。

# Reviewer

先读 [目标与方案](references/design.md) 与 [证据契约](references/contract.md)。保持规格、规则、运行、视觉和体验五层判断分别可见。

1. 读取原作约束与改编决策，建立本次必验清单。确认候选指纹、上游版本和支持的运行时；不把测试器自身假设当游戏需求。
2. 原多界面 bundle 运行 `python scripts/validate.py bundle.json` 做静态检查。单房间 `canvas-room-v1` 用 [原生验收](references/room-review.md) 的 `scripts/review_room.py`，不要把 room.json 塞入旧解释器。记录条件、终局、死锁或边界反例。静态通过仍为运行未验证。
3. 检查实际构建与清单。用 `--artifact-dir <目录>` 绑定资源和构建指纹。缺失或被改写的文件是失败，不能只确认 index.html 存在。
4. 在独立浏览器上下文，以真实点击、键盘或触控执行旅程。覆盖开始、核心机制、被拒绝交互、全部声明终局、暂停、存档恢复、坏存档和重开；记录每步只读状态、错误和截图，禁止写观察状态通关。
5. 将宿主实测证据交给 `--evidence <文件> --require-runtime` 检查。JSON 的内部一致性不证明浏览器真的运行过；可信执行记录必须来自宿主测试进程。缺少运行证据时明确未验证，不手填 passed。
6. 对照原作检查知识泄漏、因果和新增分支标记；查看截图及真实操作检查遮挡、文本可读、触屏和风格；乐趣与偏好需要玩家证据，不能由自动通关推出。
7. 缺陷报告包含阶段、输入指纹、复现动作、预期/实际、严重性、证据与应修模块。只修负责模块，最多两轮有依据的自动修复；重跑受影响检查及关键回归，旧发布保持不变。

本技能不是发布按钮，也不能认证不受信的证据文件。有限模型范围外的动态代码、网络或物理必须补充原生引擎测试。独立任务见 [评估](references/evaluation.md)。反例运行 `python -B -m unittest discover -s tests -v`。
