# Reviewer 实现前决策

目标：独立判断某候选到底通过了什么、失败在哪里，并把修复退回负责技能。效果是坏包、假通过、过期证据不能混入可发布候选，语义/视觉/乐趣缺少证据时诚实保留 unknown。

候选方案：让生成模型自评容易把自述当证据；只运行结构校验会遗漏实际绑定；分离静态、有限模型、文件完整性、真实浏览器和人工语义层可以明确每项证明边界。选择分层验收，并把哈希核对、轨迹重放和证据一致性做成独立脚本。

审核不修改输入、不删难以通过的门槛、不写 ready。所有结论绑定 bundle 哈希和候选文件哈希；任何改动使旧证据失效。浏览器证据必须包含独立 runner 标识、真实控件动作、按步观测、页面错误和候选身份，不能仅提供 passed:true。审核脚本可以发现内部矛盾与篡改，但无法凭一份可任意编辑的 JSON 证明浏览器真的运行过；可信 runner 的执行日志与受控证据位置仍是宿主责任。

验证计划：有效报告、缺浏览器证据、旧 bundle、文件篡改、证据路径穿越、假通过、动作序列与观测不符、pageerror、遗漏必需旅程、搜索截断。自动通过必须保留具体范围，不能推导美术偏好/叙事忠实/乐趣，也不能把 blocked 当 failed 的游戏设计问题。

修复有界：每个缺陷包含归属、预期、实测与最小复现；修复创建新候选，重新跑受影响层。取消/中断/环境故障必须明确记录而非放宽验收。
