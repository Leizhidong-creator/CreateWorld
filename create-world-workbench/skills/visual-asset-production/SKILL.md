# 美术资产生成

本项目编辑源在 `.agents/skills/`，工作台通过 `skills/manifest.json` 与 `cw_read_skill` 加载同步副本。正式游戏接入时另读 [工作台合成验收接口](../art-direction/references/visual-standard.md)，将共用规范记录到 `design.json.artDirection`；该接口只规定字段与证据，不覆盖本包的画法和剧本尺度。当前 World Kit 的640×360是宿主视窗合同，不是人物或图集尺寸模板。若新版制作需求超出现有宿主能力，明确报告缺口，不伪报资产类型。

这是一个完整的美术资产生产板块。对外使用本入口；内部按任务读取统一美术、固定界面、场景、角色和道具五个模块，不要求调用方分别组织技能调用。内部模块保留现有路径，以复用工艺、脚本和宿主接口，不复制维护第二套规则。本技能不要求多代理或并行代理。


## 当前项目美术基线（用户指定）

制作前必须读取并执行[星露谷式像素画法、固定视角与剧本尺度](../art-direction/references/stardew-pixel-profile.md)。保持星露谷式简洁像素语言与固定正交斜俯视；人物与场景、其他人物、建筑和道具的大小关系按本次剧本及具体要求规划，不固定人物占屏比或一格宽两格高。16×32人物与16×16地块仅作原作画法参考，不强制导出尺寸。逻辑尺寸、视窗、显示倍率与动作留白按本次尺度规划记录，保留原生母版，不默认128×128；旧兼容工艺尺寸不得覆盖本次需求。尺度补全不新增剧情与玩法。

## 一、接收完整需求包

输入是上游已完成的剧情、玩法及详细资产需求，明确要生成哪些场景、角色、道具，以及对应形态、状态、方向、动作和交互关系。原始用户描述、剧本或公开原作只是需求中的背景与视觉证据，不是本板块重新分析和规划资产的入口。

按需读取 [输入与交付约定](references/input-output.md)，接受项目已有数据结构，不强制调用方改成一套新格式。核对稳定资产ID、指定范围、明确约束和依赖关系；需求包只读。

- 不新增、删除、合并资产，不改剧情顺序、角色职责、功能、状态转换、触发条件或玩法效果。
- 可以补全未细定的美术与制作参数，例如材质、配色、姿态表达、帧时长、锚点和精确碰撞坐标；已有明确值时必须遵循。
- 未规定的导出格式、拆帧、预览和记录是制作衍生文件，不构成新增剧情资产；按实际交付需要生成，不扩大玩法范围。
- 缺项、矛盾或无法实现时，输出带资产ID的问题及建议，由上游修改需求；继续不受影响项，不自行补写玩法，也不让用户重复填写已提供内容。

## 二、建立共用美术规范

先读取 [统一美术规范](../art-direction/SKILL.md)。依据需求中的明确定调、允许补全的视觉信息或指定原作参考，为本次全部资产建立一份共用规范；已有有效规范时复用，不重复定调。

- 游戏视窗与全屏场景统一16∶9、2D像素风格；独立角色、道具和图集按用途确定尺寸。
- 优先保留原画尺寸，不默认48×64或128×128。
- 统一投影、像素画法、色板、描边、材质、光照和阴影关系；世界尺度依据剧本和具体要求规划，在同一场景内保持自洽，不把不同体型统一为相同身高。
- 区分风格参考、角色身份参考、道具参考和布局参考的用途。
- 记录风格版本及需求来源，后续全部生成和局部修复沿用该版本；风格变化必须核对受影响资产。

原有三种情况仅决定指定资产的视觉依据：外观已明确、外观未细定、存在公开原作参考。不能据此重新选择资产。

共用规范确定后，调用[固定界面风格统一](../game-ui-styling/SKILL.md)，实际适配目标游戏已启用的摇杆、交互按钮、地图、发现提示、对话、背包、存档继续和暂停界面。该模块与场景、角色、道具共用同一风格版本，不改操作或玩法；界面采用可读的平面布局，不机械套用世界视角和人物尺度。未启用的功能不因换肤而开启。仅制作离线资产且未提供目标工程时记录界面未接入，不宣称整套游戏界面完成。

## 三、按清单制作内部资产

按依赖组织生产，不机械固定所有任务顺序。场景布局、角色比例、道具尺寸可先相互核对；角色动画依赖身份母版，持物与骑乘动作还依赖对应道具。没有分配的类别不额外生成。

| 内部模块 | 读取入口 | 本板块中的职责 |
| --- | --- | --- |
| 固定界面风格统一 | [game-ui-styling](../game-ui-styling/SKILL.md) | 统一美术规范之下，实际适配已启用固定界面的样式、必要素材与状态，保留原有功能 |
| 场景生成 | [scene-generation](../scene-generation/SKILL.md) | 按固定场景清单制作背景、布局、碰撞、出入口与交互站位 |
| 角色生成 | [character-generation](../character-generation/SKILL.md) | 按固定角色/形态/动作清单制作三视图、指定基础移动与特殊动作 |
| 道具生成 | [prop-generation](../prop-generation/SKILL.md) | 按固定道具/状态/动画清单制作外观、变化和组合定位 |

执行所选模块时实际读取其入口，再按需要读取具体工艺参考。保留原生母版、生成记录、处理变换和失败诊断。需要生成角色、场景或道具图像时使用可用的原生图像工具，不以代码绘制替代生成姿态，不静默切换付费服务。固定界面的边框、按钮和图标按 game-ui-styling 优先复用现有 CSS/SVG/Canvas，只在需要复杂原创装饰时生成图片。

角色三视图确定身份后，所有方向与动作实际引用同一形态母版。正常人类行走必须对侧手脚配合，顺拐与重复相位必须修复；非人类和有依据的特殊步态按其运动方式检查。

道具、角色和场景的重复元素明确归属：例如手持碗、椅子或骑乘对象若已包含在动作图中，组合时不能重复绘制。生物兼具角色与骑乘用途时，复用同一身份，不产生两套外形。

## 四、在本板块内完成组合核对

在本次已有读图、动作预览和组合核对中执行[素材与内容边界](references/content-boundaries.md)：允许正常武打、少量血迹和正常恋爱，禁止色情与过度血腥、残酷呈现。实际看结果，不凭关键词或服装拦截；记录复用现有 notes/issues，不另设审核轮次、调用或逐项审批。上游需求冲突返回上游，不擅改剧情或资产范围。

以下属于本板块的内部质量要求，不另设“实际生产与审图提示词”技能模块：

1. **清单对应**：逐项核对ID、方向、形态、状态和动作，既不遗漏，也不扩充。
2. **风格一致**：场景、人物、道具共用世界投影、颗粒、比例、配色和光照；固定界面沿用画法、色彩与材质关系，同时保持平面可读性和触控尺度，不套用世界投影。按实际游戏尺寸组合核对。
3. **角色与动作**：身份、服装、非对称侧别稳定；逐帧及连续播放检查步态、支撑、接触和循环。
4. **空间与组合**：尺寸、脚点、握持点、骑乘点、遮挡、出生点、操作站位和碰撞对应，不能通过隐形墙修补错误画面。
5. **状态与机制对应**：图像和事件满足上游指定的转换与效果；素材自身不代表交互逻辑已经实现。

质量失败只回到对应模块局部修复，沿用全局规范和身份母版，遵守模块的有界修复次数。若修复必须改变需求，返回上游；仍失败时交付部分结果和诊断，不伪称全部通过。

## 五、统一交付

以一个资产包交付共用风格记录、清单内素材、必要动画/图集/几何/元数据，以及清晰的逐项完成状态；固定界面任务同时交付已接入的样式/配置/必要素材、组件覆盖表、实际截图和功能验证记录，未接入项明确标记。具体记录见 [输入与交付约定](references/input-output.md)。

区分已生成、已确定性检查、已视觉检查、已连续播放、已接入游戏实测，未执行的检查标记未验证。只有全部指定资产和必要检查完成时才报告本板块完成；不以预览图或生成成功代替可玩性验证。

复用现有工作台工具与内部模块路径。本封装提供统一技能入口和工作组织，不自动新增宿主的道具任务类型、运行时机制或图片服务能力；能力缺口明确返回调用方，不伪报资产类型绕过检查。
