# 可玩场景生成


## 当前项目美术基线（用户指定）

制作前必须读取并执行[星露谷式像素画法、固定视角与剧本尺度](../art-direction/references/stardew-pixel-profile.md)。保持星露谷式简洁像素语言与固定正交斜俯视；人物与场景、其他人物、建筑和道具的大小关系按本次剧本及具体要求规划，不固定人物占屏比或一格宽两格高。16×32人物与16×16地块仅作原作画法参考，不强制导出尺寸。逻辑尺寸、视窗、显示倍率与动作留白按本次尺度规划记录，保留原生母版，不默认128×128；旧兼容工艺尺寸不得覆盖本次需求。尺度补全不新增剧情与玩法。

## 输入与职责边界

接收上游已确定的完整剧情玩法需求、详细场景清单与稳定ID、场景连接、必需元素、交互与状态要求，以及共用美术规范。只将指定场景落实为画面、布局和空间数据；原剧本或公开原作仅用于核查视觉参考。
不新增、删除、合并场景，不重排剧情，不更改场景用途、出口目标或机制条件。可补全未规定的材质、陈设表达和精确坐标，但不能改变规定的拓扑、操作关系与必留元素。需求缺失、矛盾或空间不可实现时，返回带场景ID的问题与建议，交由上游修订需求；不自行删改后继续冒充原需求完成。

## 统一标准

- 游戏画面与全屏场景统一16∶9、2D像素风格，继承项目美术规范中的投影、像素尺度、角色比例、配色和材质。明确世界尺寸与视窗的关系；可滚动世界不要求地图本身为16∶9。优先保留原画尺寸，按明确交付尺寸制作，不默认128×128。
- 按上游场景清单逐项制作，不自行筛选或扩充。读取每项已确定的剧情用途和操作目标；用途缺失或疑似冗余时向上游报告，不擅自删减。
- 内容简洁，完整保留指定结构、道具与交互元素。允许减少未指定的装饰细节，不删除需求包中明确的资产或功能。不设所有场景通用的物品数量上限。
- 入口、出口、主路线、实体障碍和交互目标结构明确，主要操作区域有足够视觉留白。门、路、家具与角色实际碰撞尺寸匹配。
- 可见结构与通行规则一致：墙体不可穿越，看起来可通行的道路确实可走；不出现空气墙、穿墙或卡住角色的问题。剧情锁定的门或封路应有可辨认的视觉状态。

## 指定场景的三种视觉转译方式

1. **外观明确**：遵循需求包的建筑、陈设、空间参考和局部定调，转换为统一像素画法。
2. **外观未细定**：只为已列出的场景，根据其已确定的地点、时代、用途和角色尺度补全视觉细节。场景清单本身缺失不属于这种情况，应返回上游。
3. **有公开原作依据**：按上游指定版本核查该场景的代表性外观。上游已完成改编的玩法和场景范围保持不变，不重新选择、合并或复原被上游删去的地点。

## 生成前确定的场景说明

复用上游场景连接与稳定ID，核对以下已确定信息，并补充制作所需坐标与视觉数据。输出关联需求包版本和风格版本，不覆盖上游剧情玩法字段：

| 项目 | 必须明确的内容 |
| --- | --- |
| 剧情用途 | 事件、线索或人物变化，以及本场景的必要性 |
| 玩家任务 | 玩家要做什么、完成条件、对后续剧情的影响 |
| 连接关系 | 入口、出口、前后场景ID、转场条件与落点 |
| 必留元素 | 标志性结构、必要道具、交互对象及相对位置 |
| 空间布局 | 世界尺寸、坐标映射、可走区域、实体障碍、通道、出生点和交互站位 |
| 状态变化 | 开门、移除障碍等事件对画面、碰撞和互动条件的影响 |
| 视觉表现 | 共用美术规则、构图焦点、局部光照及遮挡关系 |

## 空间与交互标准

- **安全进入**：出生点和转场落点处于可走区域，不与障碍重叠；有足够移动空间，不会刚进入就误触返回出口。
- **可达且可操作**：使用runtime实际脚底碰撞尺寸与规则检查通道宽度、转角和站位。关键交互对象附近有可达操作位置，触发范围不落在家具或墙内，不允许无依据的隔墙互动。
- **遮挡可读**：高墙、屋顶和树木不能长期遮住关键路线、角色或交互目标。必要遮挡明确前后层关系，采用项目支持的显示方式；不能只在提示词里承诺运行时尚未实现的透明或隐藏功能。
- **状态同步**：开门、封路、移动障碍等变化后，图像状态、碰撞与交互条件保持一致，并复查受影响的路线。
- **正交尺度**：固定正交视角下不出现地平线、天空或消失点，远近人物、门与地砖保持同尺度。场景图不含UI或意外角色，人物由运行时绘制。

## 生成、核对与修复

先验证布局可行，再用原生生图制作背景：项目美术规范控制画法，布局参考控制几何，原作或用户空间参考提供环境依据。提示词明确必留元素的位置关系、入口出口、主路线、留白和禁止遮挡区域，避免只写“结构清晰、可以行走”。

空间生产读取 [碰撞规范](references/collision-spec.md)，执行 scripts/scene_collision.py validate/guide/render。碰撞覆盖图由程序叠加，不让生图模型重画碰撞版本。实际查看背景与覆盖图，核对可见地面、墙体、门口和障碍的接触位置；不能只凭尺寸相同宣称对齐。

可走多边形的闭合外框不代表实体墙；工作台出口在区域内部通过情境键转场，不能因红框闭合就判出口不可用。但真实画面仍须让边界和出口用途可理解。

在游戏实际运行中，以角色实际碰撞尺寸测试入口到必要交互点、出口的路线，检查转场落点、交互触发、遮挡与受剧情状态影响的通行变化。确定性几何检查与读图不能替代真实操作；未实际运行时，明确标记该项未验证，不宣称已消除空气墙或穿墙。

小范围画面漂移可修正对应几何；改变关键出口、障碍或机制位置须重新验证相关路径。不能用隐形墙掩盖画面错误。最多两次定向生成，保留母版、变换和失败诊断；仍无法满足要求时保留问题记录，不伪称通过。无权覆盖已接受版本。

在 Create World 工作台内使用时，先按需读取 [项目接入约定](references/workbench-v2.md)。技能可在完整任务中重复调用，不规定固定流水线。旧格式参考仅用于对应旧项目，不能覆盖当前合同。
