# Main Flow：实现前目标与决策

目标：把玩法循环与改编范围组织成能够从开始走到结束、能理解操作、能失败恢复、能退出重来的游戏主流程，并明确地点、全屏页面和覆盖界面的生命周期。

预期效果：主流程不是情节摘要。每个节点说明玩家目标、操作、完成反馈与出口；界面切换不会丢失世界状态，覆盖界面关闭后回到正确上下文。主线必需内容和可选内容分开，不因彩蛋或支线遗漏阻塞结局。

方案比较：线性关卡列表对长篇叙事简洁但不能表达返回、失败和界面栈；自由图能表达复杂流程但易出现不可达节点与没有出口的环；采用有限主流程图、显式边类型和屏幕定义，同时执行可达性及终结路径检查。具体门槛条件交给 State/Interaction，不在流程中复制第二套世界状态。

范围：检查离散流程拓扑与生命周期契约，支持多地点回访、小游戏、覆盖 UI 和多个结局。拓扑可达不代表状态门槛可达，后者必须由 State/Reviewer 的实际规则探索验证。不能从图通过推导碰撞、操作感和可读性合格。

核验计划：从入口检查所有必需节点、教学到进阶的顺序、每个非结束节点到结局的路径、失败恢复、结束后重开、覆盖界面返回、边与动作引用、所有结束节点的可达性。反样本删除结局边、孤立教学、破坏覆盖返回、把可选节点变通关必经点、失败死路。前向试作覆盖调查工作台、可失败潜行、多地点资源调配。

方法依据：项目制作架构报告中状态共享、覆盖 UI 与实际操作测试的结论。本地规则仅限声明的契约，不修改现有技能。
