# 统一美术规格与合成验收

本文件保留工作台的字段和截图验收接口。2026-10-31 起，美术生产由 `visual-asset-production` 统一入口组织；画法、视角、尺度、三视图、步态和资产清单职责以新版模块及 `stardew-pixel-profile.md` 为准。以下示例不构成固定色板、人物尺寸或占屏比。调整实际显示尺寸后须同步规格并重新检查。

目标是同一作品看起来由同一套美术制度制作。保持用户选定的风格；不固定套用本次房间的配色、比例或颗粒，不要求用户重复审批。美术一致性与玩法正确性分别验收。

## 唯一规格

在正式素材生产前建立或沿用 `design.json.artDirection`。字符描述必须具体到能指导生成，不只写“像素风”“统一风格”。必填字段：

```json
{
  "pixelPolicy": "说明逻辑画幅、有效像素颗粒、采样和缩放规则",
  "camera": "说明俯视角度、投影和物体各面的可见程度",
  "characterSize": "说明角色显示尺寸、身高与门/桌的比例、脚点",
  "palette": ["#334452", "#9eafb5", "#c7b68e"],
  "lighting": "说明主光方向、明暗层级和角色/家具投影规则",
  "detailDensity": "说明角色、家具、墙地面共享的纹理密度和轮廓处理",
  "assetReuse": "说明哪些资源沿用、匹配依据；不匹配时适配或替换",
  "referencePaths": ["references/本作选定的视觉参考.png"]
}
```

示例色板仅解释结构，不能当成本作默认答案。`referencePaths` 是工作区内真实存在、已实际查看的共同视觉参考图片，相对工作区路径。参考可以是用户提供、已有已接受素材或新制作的风格样张。布局引导图只能证明几何，不能单独当作美术风格参考。保留与本作相关的身份和服装要求。

## 素材生产与复用

背景、角色、家具与动作生成共用规格和参考，并在生成提示中说明该资源如何匹配它们。分别看起来好看不足以交付。首组角色与场景完成后，以游戏实际显示尺寸合成查看，再扩展其他资源；可用运行截图或预合成图，不要求另建展示系统。

资源格式不决定风格。SVG、PNG、旧素材或新生图都检查实际效果；不能把“同属像素风”、尺寸相同、只换配色当作匹配证据。背景中的桌子等烘焙物件也属于合成画面的一部分。若角色明显简化而背景纹理细密、视角冲突或比例失衡，适配或替换不匹配资源，不默认降低已接受素材质量。

灰盒允许使用简单形状验证玩法。未经统一美术检查的复用资源只能算临时素材。美术规格改变后，重新检查受影响的角色/背景/家具组合；旧截图和旧审阅不能证明新组合通过。

## 正式审阅

在实际游戏中查看每个本次范围内场景的合成截图，同时检查原生逻辑尺寸和放大后的效果。按以下六项记录 `pixelScale`、`projection`、`proportions`、`palette`、`lighting`、`detailDensity`：

- 像素颗粒和采样是否一致，有无清晰度差异或模糊插值。
- 角色与家具是否遵循相同视角，脚点、遮挡与地面接触是否合理。
- 人物与门、床、桌的尺度是否合理。
- 色板、饱和度、对比度与轮廓是否属于同一作品。
- 角色、家具与背景的主光方向和明暗层级是否协调。
- 简化程度、材质纹理和细节密度是否协调，有无明显贴纸/拼贴感。

`review.json.visualConsistency` 记录每个场景 `{sceneId,screenshot,checks}`；`screenshot` 使用宿主证据中的相对路径，`checks` 按上述六个键分别写 `{passed:boolean,observation:string}`，观察必须说明实际画面。无人物的场景说明检查了哪些环境物件，不虚构角色证据。发现明显不一致应令该项、`visualPassed` 和总 `passed` 为 false，修复后重新实测和审阅。不影响整体一致性的小瑕疵列为建议，不要求零瑕疵。

宿主只验证规格、证据关联和审阅覆盖，不能从 JSON 自动判断审美；语义结论必须来自模型实际读图。缺图或未查看时不得填通过。
