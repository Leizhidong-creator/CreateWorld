# 道具生成规则


## 当前项目美术基线（用户指定）

制作前必须读取并执行[星露谷式像素画法、固定视角与剧本尺度](../art-direction/references/stardew-pixel-profile.md)。保持星露谷式简洁像素语言与固定正交斜俯视；人物与场景、其他人物、建筑和道具的大小关系按本次剧本及具体要求规划，不固定人物占屏比或一格宽两格高。16×32人物与16×16地块仅作原作画法参考，不强制导出尺寸。逻辑尺寸、视窗、显示倍率与动作留白按本次尺度规划记录，保留原生母版，不默认128×128；旧兼容工艺尺寸不得覆盖本次需求。尺度补全不新增剧情与玩法。

## 输入与职责边界

接收上游已确定的完整剧情玩法需求、道具清单与稳定ID、外观约束、用途、获得/使用条件、效果、状态及转换、必要方向与动画、关联角色和场景，以及共用美术规范。本技能负责指定道具的视觉与制作细节，不负责从原始故事发现道具或重新设计使用逻辑。
不新增、删除、合并道具，不改变功能、消耗规则、状态转换、角色能力或剧情效果。未细定的材质、轮廓、状态差异表达、握持点与精确碰撞坐标可结合既定需求补全；已有明确值必须遵循。玩法缺失、矛盾或必要资产漏项时，返回带道具ID的问题记录，由上游修订，不能用推断填入新的玩法。

## 统一标准

道具包括清单指定的物品、线索、工具、机关、马、飞天扫帚或车辆等移动与骑乘对象。读取每项已确定的用途，逐项制作；不得自行以“无用途”删除条目。装饰是否独立交付或烘焙进场景遵循上游归属，不重复生成。

遵循项目2D像素美术规范，与角色、场景保持共同的像素颗粒、配色、光照与世界尺度。尺寸按用途、剧本体量和显示需求确定，不默认48×64或128×128；游戏画面的16∶9不约束独立道具和动画单元。

**交互逻辑、持有与骑乘关系、碰撞与操作范围、状态连续性均以完整需求包为依据，只推导其制作参数与视觉表达。**不要求用户重新填写上游已经确定的内容。记录明确约束与视觉补全的区别，输出关联需求包版本、风格版本和资产ID。

## 指定道具的三种视觉依据

1. **外观明确**：遵循需求包的形状、材质、配色和关键特征制作，使用逻辑及状态按已有清单执行。
2. **外观未细定**：只为清单内道具，根据其时代、用途、场景与角色比例补全外观，不新增道具、功能或状态。
3. **公开原作参考**：按指定版本核查该道具外观并保留辨识度；文字原作按描写补全视觉细节。原作只提供视觉依据，不改变上游已经确定的操作、触发、限制或结果，不补回未列出的经典道具。

## 按功能组织

- 剧情与线索：钥匙、信件、信物等，用于解锁事件或提供信息。
- 使用与消耗：食物、药品、材料等，使用后改变状态、产生效果或消耗。
- 工具与机关：作用于明确对象，完成开启、修理、搬运或解谜等操作。
- 移动与骑乘：马、扫帚、车辆等，需匹配角色、运动和碰撞。

同一道具可具有多个功能。马等生物若同时承担独立角色的叙事与行为职责，按角色生成规则制作身份、三视图和所需基础动画，道具规则负责骑乘与使用关系；复用同一身份素材，避免重复生成不一致的两套形象。

## 将四类既定要求转成素材参数

### 一、交互逻辑

读取上游确定的出现地点、获得方式、使用操作、对象、条件、效果及消耗规则，将所需可见反馈对应到指定图像、状态或动画事件。不自行补写触发条件与效果。图片负责表现，实际效果由游戏逻辑实现。

### 二、持有与骑乘关系

根据上游已指定的拿取、携带、挥动或骑乘行为，将关系细化为握持点、骑乘点、朝向、遮挡、配合姿态及指定衔接的制作参数。结合已确定角色比例与道具体型选择尺寸，避免穿插、悬空或比例失调；未列出的上下骑乘动作须报告上游，不能擅自增加。
固定身体侧别和道具非对称特征，不能盲目镜像。角色动作引用角色身份母版；组合图或独立叠加均保持同一形象。下骑乘落点应安全可达；具体骑乘移动与落点规则由运行时实现。

### 三、碰撞与操作范围

按需求包规定的阻挡、推动、摆放与操作关系细化碰撞占地、操作站位和触发范围坐标，不能自行改变是否可推动或阻挡。尺寸、定位与实际角色碰撞规则匹配，防止隔墙拾取、穿墙骑行和下骑乘卡住。
道具移动、机关启闭或骑乘状态改变后，同步更新必要的碰撞和交互范围。不能用画面动画代替逻辑变化，也不能用隐藏障碍弥补错误画面。

### 四、状态连续性

按上游状态及转换表制作，例如完整→被咬、干净→沾染或关闭→开启，不自行增加中间状态。相同道具各状态保持主体比例、配色、定位和关键特征，只改变指定部分；关键差异在游戏实际尺寸下可辨。
遵循已确定的持久性、可逆性、消耗和重置规则，避免拾取后重复出现、消耗后继续使用或切场景后无故恢复。

## 静态、形态与动画的取舍

按上游规定的表现形式与交付状态制作；仅当表现形式未规定时，在满足清单的前提下选择最小充分素材量，不能借减工作量删减指定状态、方向或动画：

| 表现形式 | 使用条件 |
| --- | --- |
| 单张静态图 | 无需表达影响理解或操作的变化 |
| 多状态图 | 外观差异本身是线索、玩法条件或必要反馈 |
| 简短动画 | 运动过程、操作时机或连续反馈影响体验 |

苹果、马和扫帚均按已列出的状态、方向与动作制作，不因常见使用方式自行增加被咬、骑行或飞行资产。承担角色职责的生物按上游归属复用角色规则，不建立重复身份。未指定的帧数与速度可按可读性补全；循环与关键事件已有规定时不得更改。

## 生成前记录与交付检查

在项目现有结构中引用道具ID、来源、用途、状态表、交互和关联对象，并记录外观、尺寸、方向、定位、碰撞与动画参数。清楚区分上游只读需求与补充制作数据，不覆盖原始玩法字段，不要求用户重复提供技术表格。

使用全局风格参考、已有角色母版及道具基准图分别控制画法、组合关系和身份。生成后保留原始母版与记录，导出适用的透明图或图集及必要元数据；各状态和帧保持定位关系，特殊动作保留有意位移。

检查游戏实际尺寸下的辨识度、透明边界和状态差异，连续播放检查动作，并实际验证拾取、使用、消耗、机关或骑乘的必要路径与状态变化。未实现或未运行的交互明确标记未验证，不能仅凭图片声称可玩。失败优先局部修复相关状态或动作，同一输入最多两轮有依据的修复，仍失败保留诊断。

本规则规定设计与素材要求，不代表宿主已支持独立道具资产任务。接入时核查当前工具、配置与运行时能力，沿用可用接口；不将道具伪报为场景或角色以绕过检查。需要新增能力时明确缺口。
