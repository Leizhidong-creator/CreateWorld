# Interaction Generation：目标与方案决定

## 目标和可观察效果

把故事事件、机制规则和空间锚点转为玩家真正能执行的操作协议。每项交互要回答：在何处、如何输入、条件不足看到什么、成功改变什么、失败如何恢复、取消如何退出、重复执行会怎样。

成功产物能直接交给组装器绑定输入和权威动作，并能从正常、失败、取消、重复及跨界面重入五个方向执行核验。不能只有“玩家修好设备”这样的自然语言摘要。

## 候选方案与取舍

1. 统一 inspect/activate/choice 模板：易实现，但再次限制机制表达。
2. 每次自由生成完整网页：可表达任意机制，却难以保持共享状态与存档一致。
3. **选用输入绑定 + typed command + 明确结果的模块契约**：标准交互复用宿主适配，自定义玩法由模块实现；交互包声明输入、结果、取消与重复策略，世界效果仅通过共同动作执行。

依据：[W3C SCXML](https://www.w3.org/TR/scxml/)将条件、事件和迁移作为状态机语义分别表达。本技能采用显式条件和事件结果的思想，并未实现或宣称兼容 SCXML。核对日期 2026-10-10。

## 边界和风险

本技能不重新决定核心玩法，不直接改写世界状态类型，不把按钮说明当可运行代码。坐标与碰撞由 Scene 产物验证；动作动画由 Character 提供；缺少模块实现时明确列出阻塞项。规格可回放通过不等于键鼠、触屏或焦点生命周期已经在浏览器里通过。

## 核验方案

正例验证证据调查、维修成功/失败/取消和重复幂等。反例覆盖不合法输入声明、悬空动作、失败无反馈、取消提交成功奖励、一次性操作重复获利及未触发前置条件。独立前向任务覆盖实时机关、拖放拼接和可中断协商。
