# Game Assembly 实现前决策

目标：把已验证的制作产物变成实际可运行候选，并确保界面切换、输入、状态和结局来自同一契约。效果是离线打开包即可开始、操作、恢复和结束，缺少资源/引用时构建失败，上一版候选保持不变。

候选方案：由模型自由拼 HTML 简单但没有可靠依赖检查；直接导入大型游戏工程需要引擎和素材管线；确定性多界面灰盒组装器可以现在验证技能接口。选择第三种作为可执行基线，并把引擎级任意玩法/动画集成清楚保留为单独需审查的扩展路径。不得以此基线冒称已具备商业游戏品质或 Phaser 全功能。

构建前校验状态、screen/action 绑定、入口、终局与资产。组装器只执行固定自带模板，不执行 bundle 中代码，不读取远程资源或任意文件。仅复制声明的本地安全资产，拒绝绝对路径、父目录、符号链接/reparse point、设备名、脚本文件。JSON 文本作为数据转义，不能变成 HTML/脚本。

输出采用新目录独占创建，每个包记录输入哈希、文件哈希和运行时版本；已有目录拒绝覆盖。失败保留诊断但不生成 ready。界面控件通过权威 reducer 发动作；测试观察接口只返回副本，不提供设置状态入口。存档导入执行同一合法性检查，暂停恢复不改变世界值。

验证计划：离线构建、真实按钮通关、跨界面知识门槛、暂停/存档恢复、结局/重开、中文和特殊字符、移动布局；故意缺 action、缺 screen、资产穿越、同名覆盖、恶意 HTML、无解状态均应失败或被隔离。浏览器 QA 必须由独立 runner 产生真实点击证据，生成 HTML 成功本身不算通关。
