# 检查与证据

## 视觉

- 实际游戏画面中同时检查主体场景/角色与固定界面，不能只看独立组件效果图。
- 至少查看桌面横屏和手机横屏（可默认1366×768、844×390，项目规定尺寸优先），确认按钮和字不被截断、控件不遮住关键目标、触控区未缩小。
- 打开对话及选项、地图、背包详情、发现列表、暂停及其实际子页、标题继续入口，核对字体、边框、配色、图标和焦点一致。测试长中文、空列表、禁用和未发现状态。
- 检查摇杆底座/头和地图Canvas内部是否真正适配，不只检查外围CSS。未知信息保持未知，地图标记和图例语义不变。

## 操作

- 键盘移动/交互与原键位有效；触屏摇杆与交互按钮可同时操作，抬手、失焦和切后台清空输入。
- 对话第一次推进补全文字，下一次继续；选项及其后果保持原有逻辑。
- 地图打开和关闭正常；模态打开时不会误操作场景，关闭后恢复焦点和输入。
- 背包数量与详情正确，空背包可返回；启用的发现提示与记录正常且不重复领奖。
- 暂停/恢复、保存/继续与返回标题有效；使用真实存档检查恢复，不改版本或清空旧记录让测试通过。
- 未启用模块记为不适用，样本中无法到达的状态记为未验证；不得临时向正式剧情植入事件凑测试状态。可用隔离测试夹具，不计作正式剧情资产。

## 交付状态

沿用现有清单格式，记录组件、开关、实际接入文件、覆盖状态、截图、视觉结果、功能结果与接口缺口。截图必须来自实际构建，标明测试尺寸；静态截图不能证明多指操作或存档恢复。

规则或技能结构校验通过不等于游戏界面通过。本次创建技能未实际运行某个游戏时，明确只完成技能接入。
