# 基础图集与追加动作

工作台 assets-plan 的基础角色任务使用 kind:character、method:direct-grid、192×256最终图集，frameLayout为4×4，48×64单元，行down/left/right/up，列站立/步态A/站立/步态B。原生母版可更大，但必须等分4行4列，主体不能贴格边。透明或纯白背景；宿主去除边缘连通白底，以全角色统一比例做最近邻缩放，并将行走帧的完整轮廓平移至统一脚底基线；不修改人物姿态。特殊动作保留画面内位移，不套行走对齐。保留非对称特征，不能盲目左右镜像。

正常人类行走必须对侧手脚配合：左腿前迈配右臂前摆，右腿前迈配左臂前摆。身体左右与画面左右分开说明，侧视图明确近侧/远侧；同一侧手脚前后相反，两步态帧实际交换肢体相位。逐帧读图后再连续播放，顺拐、重复迈同一腿或朝向错误必须修复，不能列为摆臂幅度警告。持物、受伤等剧情特殊步态和非人类另按其运动方式检查。整图失败时可按方向生成并记录组装关系，不镜像非对称服饰。帧像素不同不等于步态正确；packSpriteGrid的差异检查不验证手脚解剖关系，不能据此宣称无顺拐。

特殊动作使用 kind:action、entityId:<角色ID>、actionName:<动作名>、grid:{columns,rows,cellWidth,cellHeight,fps,anchor?}、events:[{frame,name}]。width/height必须等于网格×单元；至少两帧实际动作变化。背景透明，全部帧按同一支撑点定位。动作形态决定朝向、接触与回收，不套行走步态检查。

例如敲击：预备→抬手→接触→回收，contact事件落在接触帧。攀爬：支撑点和位置移动由游戏模块控制，动作图片只负责表现。默认不循环，动画不能自动决定任务成功。

原生结果原字节保存。宿主 packSpriteGrid 检查网格、透明、截边、动作差异；独立读图检查身份和动作。确定性通过不代表姿态语义正确。最初直接图集与兼容母版工艺的质量差异须由实际生成比较，不能声称新模型必然更好。

旧母版工艺仍可用：不指定method或指定legacy-sheet，按generation-workflow.md生产3×4并执行原build_character_pack.py。不要为了满足旧工艺强制改项目风格。
