# Narrative Branch：目标与方案决定

## 目标和可观察效果

把玩家的知情选择、可选任务及过去行为变为可执行的条件、持续后果、汇合和结局。输入为已确认的改编、主流程和状态契约；输出不得自行改写原作事实或创造未登记状态。

验收看三个结果：所有承诺可见的分支存在实际到达路径；选择改变后续权限、资源、关系或明确的叙事信息；汇合后保留应持续的历史，结局有明确且可执行的冲突处理。

## 候选方案与取舍

1. 自然语言树：容易创作，但不能可靠检查条件、重入和结局冲突。
2. 强制使用 ink：适合复杂叙事，原生支持 choices、gathers、variables；但给所有宿主增加运行时，不适合已经具备状态管理的游戏。
3. **选用宿主中立的有限状态分支契约**：作者仍写分支内容，显式连接世界状态与动作；在现有状态模型上回放路径。需要 ink 时由宿主适配，不能另建一套权威变量。

依据：[ink 官方介绍](https://www.inklestudios.com/ink/)将其定位为可嵌入引擎的叙事中间件；[写作手册](https://github.com/inkle/ink/blob/master/Documentation/WritingWithInk.md)提供选择、汇合与变量方法。这里采用其设计区分，不复制或宣称执行其引擎。核对日期 2026-10-10。

## 边界和风险

分支技能不重做原作理解、不生成全部 NPC 台词、不承担场景导航。复杂连续模拟、随机事件和实时反应不能靠本包有限回放证明。模型可达性也不证明实际 UI 已绑定；组装阶段仍须真实玩家输入。无选择的忠实改编允许空分支，并解释为何不强加多结局。

## 核验方案

正例覆盖带前置条件的两路线与持续后果。反例至少覆盖未知状态、不可达选择、汇合后果丢失、相同优先级结局重叠以及虚假路径。脚本在有限世界模型中找可达性和反例；达到探索上限必须失败并说明，不能以截断当通过。独立前向任务覆盖互斥选择、跨章延迟后果及固定原作结局。
