# 从事件到分支

原作事实：桥上两组被困者共用一台升降机，维修员知道承载上限。改编决定让玩家选择先救哪组，而不改写设备上限。

先定义后果：先救伤员会失去保存货物的时间；先救工人能获得后续协作，但伤员需备用医疗路线。把优先顺序写入 enum `first_rescue`，把后续可用路线写入已有资源/任务变量。两条路回到同一大厅时保留 first_rescue。第二章 NPC 读它解释先前决定；不是先生成三篇结局文案再倒推按钮。

只有上游批准变量、动作与界面后才生成正式 `branches`。`fixtures/valid.json` 展示可运行的双结局小模型；它是人工确定性回归数据，不是任何模型生成品质的证明。

若需求是“在 2D 潜行中被哪位守卫发现，改变下一幕对话”，原生设计应额外交付：检测事件类型、时间顺序/同帧冲突策略、知情者集合、保存字段、可观察日志、成功逃离与捕获测试。有限按钮模型只能验证剧情后果投影，不能替代视野检测与角色运动。
